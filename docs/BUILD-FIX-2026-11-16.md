# Floatly Windows compile fix — 16 November 2026

## Reported problem

`02-CREATE-PORTABLE-EXE.bat` failed with 14 `CS0104` errors: the compiler saw both WPF and Windows Forms/System.Drawing definitions of `TextBox`, `Button`, `CheckBox`, `MouseEventArgs`, `Point`, and `Rectangle`.

## Implemented fix

- Disabled compiler-generated implicit `using` directives in `Floatly.App.csproj` (all app files explicitly import their dependencies). This prevents the global `System.Windows.Forms` and `System.Drawing` imports colliding with WPF controls.
- Added explicit WPF type aliases in the three affected UI source files.
- Kept `UseWindowsForms=true` because Floatly intentionally uses Windows Forms for its tray icon, monitor discovery, and the folder picker. That feature remains enabled.

## Steps

1. Extract the new ZIP to a **new folder**, not over an older extracted version.
2. Open the new `Floatly` folder and double-click `01-BUILD-AND-RUN.bat`.
3. When that succeeds, close Floatly using the tray icon, then double-click `02-CREATE-PORTABLE-EXE.bat`.
4. Find `Floatly.exe` in `out\Floatly-win-x64`.

If the compiler reports other errors, copy its **first error block** so they can be corrected.

## Verification limits

Source-code inspection and XML/ZIP validation have been performed in a non-Windows environment. A real .NET/WPF build and graphical startup test require Windows; this release has **not** been claimed as compiled/tested.
